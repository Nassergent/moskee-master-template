   - `'rate_limit_hard_fail'` — emitted when donate route returns 503 due to Redis failure

3. In `src/lib/security.ts`, make these changes:

   a. **Add imports** at the top:
      - `import { LRUCache } from 'lru-cache';`
      - `import { createHash } from 'node:crypto';`
      - `import { formatLog } from './logic/logger';`

   b. **Replace the Map** — change:
      ```typescript
      const rateLimitMap = new Map<string, { count: number; resetAt: number }>();
      ```
      to:
      ```typescript
      const rateLimitMap = new LRUCache<string, { count: number; resetAt: number }>({
        max: 500,
        ttl: 60_000,
      });
      ```
      The LRUCache `get`/`set` API is compatible with Map for this usage. `get()` returns `undefined` for expired entries, which the existing `if (!entry || ...)` guard already handles.

   c. **Add hashIp helper** (private, not exported):
      ```typescript
      function hashIp(ip: string): string {
        return createHash('sha256').update(ip).digest('hex').slice(0, 16);
      }
      ```

   d. **Update checkInMemoryFallback signature** — add `route: string` and `emitLog: boolean` parameters:
      ```typescript
      function checkInMemoryFallback(
        ip: string,
        route: string,
        maxRequests: number,
        windowMs: number,
        emitLog: boolean
      ): RateLimitResult
      ```
      After computing the result (before each `return`), if `emitLog` is true, emit:
      ```typescript
      console.log(formatLog('warn', 'rate_limit_fallback', {
        source: 'memory',
        route,
        hashedIp: hashIp(ip),
      }));
      ```
      Log on EVERY fallback activation (both allowed and denied) per RATE-06 wording.

   e. **Update checkRateLimit signature** — add `route` as the LAST parameter with default `'unknown'`:
      ```typescript
      export async function checkRateLimit(
        ip: string,
        failStrategy: FailStrategy,
        maxRequests: number = 5,
        windowMs: number = 60_000,
        route: string = 'unknown'
      ): Promise<RateLimitResult>
      ```

   f. **Add hard-fail logging** — at both hard-fail return points (catch block and timeout block), BEFORE the return statement, emit:
      ```typescript
      console.log(formatLog('warn', 'rate_limit_hard_fail', {
        source: 'hard-fail',
        route,
        hashedIp: hashIp(ip),
      }));
      ```

   g. **Update checkInMemoryFallback calls** inside checkRateLimit:
      - Redis catch block (fallback): `checkInMemoryFallback(ip, route, maxRequests, windowMs, true)`
      - Redis timeout block (fallback): `checkInMemoryFallback(ip, route, maxRequests, windowMs, true)`
      - No Redis configured (normal): `checkInMemoryFallback(ip, route, maxRequests, windowMs, false)`

   IMPORTANT: Do NOT use `ttlAutopurge: true` on LRUCache — unnecessary in serverless context (see research anti-patterns).
   IMPORTANT: Do NOT set per-entry TTL in `set()` calls — constructor-level TTL is sufficient since all entries use the same window.
