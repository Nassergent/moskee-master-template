# Plan 01-01: Sanity Write Recovery met Redis Fallback

## Context

De `retryWithBackoff()` in `webhook-service.ts:170-184` probeert 3x maar bij definitieve Sanity failure wordt de error gegooid en gaat de donatie verloren. `payment-service.ts:41-44` heeft zelfs helemaal geen error handling op de Sanity write.

## must_haves

1. Sanity write failures in webhook-service worden opgevangen en opgeslagen in Redis
2. payment-service.ts Sanity write heeft error handling
3. Reprocess endpoint kan failed webhooks opnieuw verwerken
4. Tests dekken het hele recovery pad

## Tasks

<task id="1.1" title="Add Redis failed payment storage to webhook-service">
**File:** `src/services/webhook-service.ts`

Wrap het `retryWithBackoff` blok (regels 170-184) in een extra try-catch. Bij definitieve failure na 3 retries:

```typescript
try {
  await retryWithBackoff(async (attempt) => { ... }, 3, logs, paymentId, tenantId);
} catch (sanityErr) {
  // Sanity definitief gefaald — sla op in Redis voor later reprocess
  if (r) {
    const failedData = JSON.stringify({
      paymentId,
      projectId,
      projectName,
      amountCents,
      failedAt: new Date().toISOString(),
      error: sanityErr instanceof Error ? sanityErr.message : String(sanityErr),
    });
    await r.set(`${tenantId}:failed:${paymentId}`, failedData, { ex: 2592000 }); // 30 days TTL
    log('error', 'sanity_write_failed_stored', { tenantId, projectId, amountCents });
  }
  // BELANGRIJK: ga door naar processed marker + email — donatie is wel betaald
}
```

De flow mag NIET stoppen — payment is al betaald bij Mollie, dus processed marker + email moeten doorgaan.
</task>

<task id="1.2" title="Add error handling to payment-service Sanity write">
**File:** `src/services/payment-service.ts`

Wrap regels 38-46 in try-catch:

```typescript
if (!payment.skipSanityUpdate && shouldUpdateProject(projectName)) {
  try {
    const project = await fetchProjectByTitle(projectName!);
    if (project?._id) {
      await writeClient
        .patch(project._id)
        .inc({ huidigBedragCents: paidAmountCents })
        .commit();
    }
  } catch (sanityErr) {
    console.error(formatLog('error', 'sanity_write_failed', { projectName, paidAmountCents }, sanityErr));
    // Don't throw — email should still be sent
  }
}
```

Import `formatLog` from `../lib/logic/logger`.
</task>

<task id="1.3" title="Create reprocess-failed-webhooks API endpoint">
**File:** `src/pages/api/jobs/reprocess-failed-webhooks.ts` (NEW)

Create a POST endpoint that:
1. Requires `CRON_SECRET` header match (env var) — reject 401 otherwise
2. Uses Redis SCAN to find all `*:failed:*` keys
3. For each key: parse JSON, attempt Sanity write
4. On success: delete the failed key, set processed key
5. On failure: leave the key, log error
6. Return JSON summary: `{ processed: N, failed: N, errors: [...] }`

Rate limit: no (cron-only endpoint, protected by secret).
Prerender: false.
</task>

<task id="1.4" title="Write tests for recovery flow">
**File:** `src/tests/webhook-recovery.test.ts` (NEW)

Test cases:
1. **Sanity write failure → Redis fallback**: Mock `writeClient.patch().inc().commit()` to throw → verify Redis `.set()` called with correct key pattern `{tenantId}:failed:{paymentId}` and JSON payload
2. **Reprocess success**: Mock Redis SCAN returning failed keys → mock Sanity write success → verify key deleted
3. **Reprocess partial failure**: Mix of successes and failures → verify correct summary counts

Use existing mock patterns from `src/tests/webhook-idempotency.test.ts`.
</task>
